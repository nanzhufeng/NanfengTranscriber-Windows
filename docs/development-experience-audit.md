# 南枫转写 Windows：开发经验审计与证据矩阵

> 审计日期：2026-07-19
> 正式基准：`v1.0.0` 首发行为、`main` 的平台命名规则，以及 2026-07-19 重建候选中的 API、DPI、持久模型缓存、Inno 安装器与中文安装说明回归。
> 明确排除：早期“南烛枫视频转文字”命名、被用户否定的 UI 版本、失败安装包、旧 GitHub 仓库名、仅凭截图或构建成功推断真实功能完成的结论。

## 1. 证据等级

| 等级 | 含义 |
| --- | --- |
| R | 已在真实 Windows 环境、真实媒体或真实 GitHub 服务验证 |
| A | 自动化测试或确定性检查通过 |
| B | 构建或打包通过 |
| I | 代码或文档已实现，但缺少独立运行证据 |
| D | 用户确认的设计或交互方向 |
| P | 尚未验证，只能进入风险清单 |

这些等级不能互相替代。截图存在不等于功能完成，单元测试通过不等于全新电脑安装成功。

## 3. 项目专属事实

- Windows 入口：`start.py`；UI：`app/main.py`；推理与导出：`app/transcriber.py`；API 后处理：`app/postprocess.py`。
- 默认模型 `medium`、语言中文、模式 GPU 优先；导出 TXT / Markdown / SRT / DOCX。
- 上一安装资产 SHA-256：`EE86E9596AF081857877C8694973B7F8DA94D2FC916DE95EED089DAB2F5F4DB0`。
- 2026-07-19 重建安装资产 SHA-256：`17F4611F31CA3912D426CFB511364862D76F3835EF978FD61CBAFC03F7CD17B4`。
- PyInstaller spec 仍依赖仓库外的 `..\JHlib\ffmpeg`，这是本项目构建约束，不应进入通用产品规则。
- API 环境变量名称属于兼容合同：`NANZHU_TEXT_API_KEY`、`OPENAI_API_KEY`、`NANZHU_TEXT_BASE_URL`、`NANZHU_TEXT_MODEL`。

## 4. 跨项目可复用规则

1. 长任务工具必须建立显式阶段状态，区分正常等待、下载、加载、执行、后处理、停止、完成和失败。
2. 队列型本地 AI 工具应由队列会话拥有昂贵模型/管线，逐项任务只提供输入和选项；不要重复加载。
3. GPU 降级必须只捕获明确 GPU 资源/运行库错误，不能把媒体、参数或业务错误吞成 CPU 回退。
4. 性能优化必须保存固定样本、环境、总耗时、资源占用和输出摘要；速度与质量同时验收。
5. “已有结果跳过”是继续执行合同，不是结束合同；过滤后的队列必须进入同一公开启动入口。
6. 用户可见“完成”必须以有效产物为准：文件存在、大小合理、格式可识别、内容不是错误页或空占位。
7. 本地能力与联网后处理必须分开命名、授权和报告，明确传输的数据种类。
8. 交付物按平台区分仓库、Release 和文件名；安装包、便携包和源码启动包不得混称。
9. 先验证源码或 `.bat`，再验证 EXE，最后生成安装包；每一级不能替代下一级。
10. 重复用户反馈应转化为契约测试、检查脚本或验收清单，不只写入总结。

## 5. 失败经验与禁止项

- 禁止把“界面显示 100%”当作有效转写完成。
- 禁止在批量管线中机械复用会污染每个批次的提示词。
- 禁止每个队列项重复加载相同模型。
- 禁止用宽泛异常捕获把所有错误改成“GPU 不可用”。
- 禁止让模型下载/加载只有静止的百分比而没有阶段说明。
- 禁止让复制提示、安装提示或加载提示临时改变主窗口高度。
- 禁止把旧项目名、无平台仓库名或失败安装包继续作为正式基准。
- 禁止把真实文件路径、API Key、账号数据或私密媒体内容写进共享 Skill 和长期记忆。
