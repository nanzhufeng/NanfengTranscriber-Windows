# 南烛枫视频转文字：转录性能均衡优化设计

> 日期：2026-07-15  
> 状态：已实施并完成本机 GPU 性能验证（见第 10 节）  
> 项目：`D:\CodexProjects\江湖工具箱\VideoTranscriber`

## 1. 目标

在不改变现有 UI 结构、批量队列、停止操作和导出格式的前提下，提高批量视频/音频转录效率。

本次采用“均衡档”：保留默认 `medium` 模型，允许极小的准确率变化，优先提升 RTX 4090 上的批量吞吐，同时保证无可用 GPU 时能够稳定回退 CPU。

验收目标：使用相同测试媒体、相同语言与输出设置对比优化前后总耗时，优化后总耗时至少降低 30%，抽查文本不得出现明显质量下降。

## 2. 已确认的瓶颈

1. `transcribe_file` 每处理一个文件都会重新创建 `WhisperModel`，造成重复模型加载和 GPU 初始化。
2. 队列逐文件串行执行，没有使用 faster-whisper 的 `BatchedInferencePipeline`。
3. 当前固定使用 `beam_size=5`，偏向准确率而非吞吐。
4. 历史运行日志记录过 GPU 失败后回退 CPU；当前机器已确认能够识别 RTX 4090、CUDA 设备和 `float16`。
5. 当前没有自动化测试，需要先建立最小回归测试，再修改生产代码。

## 3. 方案选择

### 方案 A：只复用模型

风险最低，只消除重复模型加载，但不能充分利用 RTX 4090 的批量推理能力。

### 方案 B：复用模型并使用 GPU 批量推理

本次采用。模型在整个队列中复用，GPU 使用 `BatchedInferencePipeline`，默认批量大小为 8，并将 `beam_size` 调整为 3。

### 方案 C：多个文件并行转录

暂不采用。该方案会增加显存争用、停止控制、进度归属和错误恢复复杂度，当前收益不足以抵消风险。

## 4. 核心设计

### 4.1 队列级转录会话

新增队列级转录会话对象，负责模型生命周期和推理管线复用。会话由 `TranscribeWorker` 在开始队列时创建，在队列完成或停止后释放。

模型缓存键由以下字段组成：

- 模型规格：`base`、`small`、`medium`、`large-v3`
- 运行设备：`cuda` 或 `cpu`
- 计算类型：GPU 使用 `float16`，CPU 使用 `int8`

语言不是模型缓存键，同一模型可以处理不同语言的队列项目。

当某一行选择了不同模型时，会话只在模型规格变化时加载对应模型；后续再次使用相同组合时复用已经加载的实例。首版允许缓存多个已用模型，但队列结束后统一释放，避免跨任务长期占用显存。

### 4.2 GPU 批量推理

GPU 模式使用 faster-whisper 的 `BatchedInferencePipeline` 包装已加载模型：

- 默认 `batch_size=8`
- 默认 `beam_size=3`
- 保留 `vad_filter=True`
- 保留 `temperature=0.0`
- 保留 `condition_on_previous_text=False`
- 中文继续使用现有简体中文提示词

批量大小首版不暴露为 UI 设置，避免增加普通用户决策负担。

### 4.3 自动降级

如果 GPU 批量推理发生显存不足或批处理相关错误，当前文件按以下顺序重试：

1. `batch_size=8`
2. `batch_size=4`
3. `batch_size=2`
4. 普通非批量 GPU 推理
5. 仅在明确属于 CUDA、cuBLAS、cuDNN 或 GPU 运行时错误时回退 CPU

成功降级后，后续文件沿用已经确认可用的档位，避免每个文件重复失败。

非 GPU 类错误不应被自动降级吞掉，仍按现有方式显示具体失败原因。

### 4.4 CPU 回退

CPU 模式继续使用 `int8`，但同样复用模型实例。首版不引入多文件 CPU 并行，避免线程过量和系统卡顿。

### 4.5 进度与停止

保持现有逐文件状态和总进度计算。批量推理仍按返回的 segment 结束时间更新当前文件进度。

停止操作继续在 segment 迭代和 FFmpeg 音频提取阶段检查取消标记。批量推理内部无法瞬时中断时，界面显示“正在停止”，在当前批次返回后退出，不启动下一个文件。

## 5. 数据流

1. 用户点击“开始转写”。
2. `TranscribeWorker` 创建队列级转录会话。
3. 当前文件完成 FFmpeg 音频提取。
4. 会话按模型和设备查找可复用实例；不存在时只加载一次。
5. GPU 优先走批量推理；失败时按确定顺序降级。
6. 生成 segments，并沿用现有 TXT、Markdown、SRT、DOCX 和可选润色输出逻辑。
7. 进入下一文件时复用模型和已经确定的批量档位。
8. 队列结束或停止后释放会话。

## 6. 影响范围

允许修改：

- `app/transcriber.py`：会话、模型复用、批量推理和降级逻辑
- `app/main.py`：让 Worker 持有并复用会话，保持现有信号接口
- `tests/`：新增性能路径和行为回归测试

不修改：

- UI 布局和视觉设计
- 默认模型 `medium`
- 语言选项和简体中文目标
- 导出目录结构和文件命名
- TXT、Markdown、SRT、DOCX 内容结构
- 转写后翻译/润色 API 逻辑
- Windows 安装方式

## 7. 测试设计

实施前先建立测试并确认失败，再编写生产代码。

自动化测试至少覆盖：

1. 同一模型、设备和计算类型在多个文件间只加载一次。
2. 不同模型规格分别加载，返回原规格时可以复用缓存。
3. GPU 默认选择批量大小 8 和 `beam_size=3`。
4. 显存不足时按 `8 → 4 → 2 → 普通 GPU` 降级。
5. CUDA 运行时错误才回退 CPU，普通媒体错误不得误判。
6. 停止请求后不再启动下一个文件。
7. 现有导出格式和输出路径保持不变。

本机验证使用 3 个代表性媒体：短视频、中等长度视频、长视频。优化前后必须使用相同输入、`medium`、中文、相同导出选项和相同 GPU 环境。

记录：

- 模型首次加载时间
- 每个文件转录时间
- 队列总时间
- 峰值显存
- 是否发生批量降级
- 文本抽查差异

## 8. 验收与停止条件

满足以下条件后停止扩大优化范围：

- 自动化回归测试全部通过。
- 源码 `.bat` 可以启动并完成代表性文件转录。
- 相同媒体队列总耗时至少降低 30%。
- 没有明显转录质量下降。
- GPU 不可用时可以明确提示并稳定回退 CPU。
- 停止、已有结果跳过和所有导出格式没有回归。

本阶段不追求多文件并行、自动选择模型或新增高级性能设置。若模型复用与批量推理仍未达到 30% 目标，再单独评估音频预提取流水线或多文件并行，不能直接叠加复杂度。

## 9. 风险与边界

- `BatchedInferencePipeline` 的进度回调粒度可能比普通推理更粗，但不应改变最终结果。
- `beam_size=3` 可能产生极小文本差异，需要用真实中文口播素材抽查。
- GPU 显存占用会高于普通推理，但 RTX 4090 的 24GB 显存足以从批量大小 8 起步；其他电脑依靠自动降级。
- 本项目当前不是 Git 仓库，设计文档可以保存，但无法按 Superpowers 流程提交 Git commit。

## 10. 实施结果（2026-07-15）

### 已实现

- 新增队列级 `TranscriptionSession`：同一模型、设备和计算类型只加载一次，队列结束后统一释放。
- GPU 使用 `BatchedInferencePipeline`，默认批量大小为 8、`beam_size=3`；遇到批处理资源错误时按 `8 -> 4 -> 2 -> 普通 GPU` 降级，并记住可用档位。
- 仅在明确的 CUDA、cuBLAS、cuDNN 或 GPU 运行时错误时回退 CPU；CPU 继续使用 `int8` 并复用模型。
- `TranscribeWorker` 整个队列只持有一个会话，停止后不再启动下一项。
- 保持既有 UI、导出格式、输出目录、文件命名、已有结果处理和翻译润色模块不变。

### 自动化与源码验证

- `python -m unittest discover -s tests -v`：9 个测试全部通过。
- `python -m compileall app tests tools`：通过。
- 导入检查：`TranscribeWorker` 与 `TranscriptionSession` 可正常导入。
- 使用 `QT_QPA_PLATFORM=offscreen` 完成源码界面构造及退出检查，退出码为 0。该检查仅证明窗口可构造，不替代人工可视界面验收。
- 使用 25 秒真实样本完成一次 `CPU 稳定 / int8` 最小回退验证，耗时 6.906 秒。

### 本机真实 GPU 基准

环境：Windows、RTX 4090、Python 3.13.3、faster-whisper 1.2.1、CTranslate2 4.8.1、`medium`、中文、GPU 优先、仅 TXT、关闭翻译润色。三个固定样本总时长约 20 分钟。

| 指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 队列总耗时 | 130.499 秒 | 28.403 秒 |
| 性能改善 | - | 78.2% |
| GPU 显存峰值 | 3923 MB | 4931 MB |
| GPU 显存增量 | 2649 MB | 3800 MB |

显存数据来自 Windows WDDM 下的整卡占用回退读数，不是进程独占显存。优化后三个样本均成功导出，无运行错误；抽查文本不再包含原先的提示词泄漏。

### 质量边界与待验证项

- `BatchedInferencePipeline` 会把 `initial_prompt` 注入每个批次窗口，实测会污染输出并造成漏字。因此批量路径刻意不传该提示词；普通 GPU 和 CPU 路径仍保留原有提示词。
- 这意味着批量路径优先保证原始转写正确性，不能承诺自动把繁体、英文或文言稳定转换为现代简体中文。需要该能力时，应启用已有的“翻译润色”模块并配置文本 API。
- 相同内容在批量与普通推理间允许存在标点、分段和少量用词差异；更高精度需求可单独评估调高 `beam_size` 的吞吐代价。
- 其他显卡、低显存设备的实际降级档位，以及超长音频的内存和停止响应，仍需在对应机器上验证。
- 本轮未重新打包 EXE 或安装包；本机验证范围是源码、自动化测试、真实 GPU 基准与 CPU 最小回退。
